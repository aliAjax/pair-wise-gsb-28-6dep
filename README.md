# 按送达顺序装车 · 拖拽排车

解决的现场问题：司机按订单拖入顺序往后堆货，先送的货被压在车厢最里，到第一个点要整车翻找。
本工具把待分配订单拖进司机卡片后**自动按送达顺序排列**——远点先装车尾、近点靠门放，开门即卸第一单。

- 技术栈：React 19 + Vite + TypeScript + dnd-kit（拖拽）+ zustand（持久化状态）
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则单测：`npm test`（14 个用例：排序、顺序冲突、超重、发车快照、重开核对）

## 业务规则

1. **送达顺序**：距仓近的先送（`distanceKm` 升序）。
2. **装车顺序**：与送达相反（降序）——最远点先装车厢最里，最近点最后装、靠车门。
   卡片上同时标注「装 N」（装车次序）和「送 N」（送达次序）。
3. **顺序冲突退回**（订单回待分配区 + 记录挡路单）：
   - 同一送达点且同距离：谁先谁后排不出来；
   - 订单的客户硬性要求（`deliverBeforeId`）与"近点先送"矛盾（远点却要求先于近点送达）。
4. **超重退回**：加入后单趟总重 > 该车核定载重即退回，写明**超出多少公斤**以及被靠门先送的哪一单挡住；
   空车单件就超限时单独提示。顺序冲突优先于超重判定。
5. **发车锁定**：发车后订单不可增删，按「车次 + 装车顺序 + 总重」生成指纹快照（FNV-1a）。
6. **换班接车**：只改当前司机并留换班记录（谁→谁、时间），车次与订单顺序不动。
7. **重开核对**：刷新/重开页面后按订单资料重新核算重量，与发车快照逐项比对，
   少货、多货、换序、重量变化（含资料里改了重量）、指纹不符都会在车卡上报出。

## 试用路径（内置示例数据）

- 把 **O-1011**（嘉定北站 25km）拖到已装 **O-1003**（同点同距）的车 → 顺序冲突退回；
- 把 **O-1012**（金山卫 55km，要求先于 O-1006）与 **O-1006**（普陀 8km）装同车 → 要求与距离冲突退回；
- 向**赵师傅**（载重 500kg）连续装 O-1007(290)+O-1005(150)+O-1003(240) → 超重 180kg 退回，点名被 O-1005 挡住；
- 装好后点「发车并锁定顺序」，刷新页面仍能看到核对结果；再点「换班登记」可交接给新司机。

## 三层分离维护

```
src/data/orders.ts      订单资料：送达点、距离、重量、客户硬性送达要求（主数据）
src/data/drivers.ts     司机/车辆资料：车次、车牌、核定载重（主数据）
src/logic/loading.ts    装载判断：排序、冲突、超重、发车快照、核对指纹（纯函数，无 React/无浏览器依赖，可单测）
src/state/dispatchStore.ts 页面状态：每车订单、发车锁、换班记录、退回记录（zustand + localStorage）
src/components/*、App.tsx  页面：布局、拖拽编排、展示，不写业务规则
```

订单资料改 `src/data/`，装车规则改 `src/logic/loading.ts`，页面互不耦合。
状态只存分配结果（key：`loading-dispatch-state-v1`），订单资料不入库——重开后用资料重新核算，避免资料改了旧分配"看起来还对"。
