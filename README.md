# 配送任务拖拽排班

- 行业：物流
- 技术栈：React、Vite、TypeScript、Ant Design、dnd-kit、zustand
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

## 解决的现场问题

司机原先按拖入顺序往后装，先送的货被压在最下面，到第一个点要整车翻找。本看板改为：

1. **拖入即排**：待分配订单拖进司机卡片后，自动按送达顺序排列——近点先送靠车门放，远点最后送、先装压里侧（每张票同时标出「第 N 站」和「装车第 N 个装」）。
2. **载重校验**：单趟总重不得超过车辆核定载重；超重的订单退回待分配区，注明「超重 X kg：本单 + 车上已有 = 合计，超过核定载重」。
3. **顺序冲突校验**：按发车时间、里程、每站停留逐点推算 ETA，赶不上订单预约送达时间即退回，注明**被哪一单挡住**、晚多少分钟；首站冲突则提示无站点可挡、建议更早发车或换车。
4. **发车锁定**：发车瞬间把送达顺序、总重、核定载重整趟快照锁定，之后换班司机只能改当班司机，顺序不动；卡片不可再拖入/拖出。
5. **重开可核对**：全部状态存 localStorage（key：`hxwlfront-14-dispatch-v1`），重开浏览器后每车的顺序和重量仍可对照；已发车的车显示的是发车时的快照。

## 代码分层（资料 / 判断 / 页面分开维护）

| 目录 | 职责 |
| --- | --- |
| `src/data/master.ts` | **订单资料层**：目的地里程、司机花名册、车辆与核定载重、路线规则（默认发车时间、时速、每点停留分钟）、种子数据。改距离/载重/规则只动这里 |
| `src/logic/loading.ts` | **装载判断层**：纯函数。送达排序、ETA 推算、超重与顺序冲突判定，不依赖 React，可单测 |
| `src/store.ts` | 状态层（zustand + persist）：订单状态、车辆运行时/锁定快照、退回记录 |
| `src/components/*`、`src/App.tsx` | **页面层**：dnd-kit 拖拽、司机卡片、新增订单表单、指标与归档，不含业务规则 |

## 判定口径（在 `master.ts` 可调）

- 送达顺序：距仓库里程升序（近先送），同里程按订单号；装车顺序反过来。
- ETA：按平均时速 40 km/h 从仓库径向推算逐点行驶时间，每站卸货停留 15 分钟。
- 冲突只检查「预约送达截止时间」（新增订单时可选填）；未填时间要求的订单不参与顺序冲突。
